# 飞书内容忠实与视觉重构契约

当船帆本人要求“按飞书文档做 PPT”、给出飞书文档链接或明确说按文档内容与顺序推进时，本文件是 P0 验收条件。

## 1. 核心原则

- 飞书文档是内容和顺序的单一事实来源。
- 主要任务是视觉重构、演讲化组织和页面设计，不是擅自重写原稿。
- 除明显错别字、事实错误、重复粘贴或用户明确授权删改外，正文内容尽可能完整保留。
- 内容过多时优先拆页、缩短说明性标签或调整图文关系，不先删原文。
- 页面顺序必须跟随飞书文档；需要合并或拆分时，在 `source-manifest.json` 中保留原始顺序映射。

## 2. 动手前建立来源清单

先生成同目录 `source-manifest.json`，至少包含：

```json
{
  "source": "飞书文档 URL 或文档标题",
  "orderedSections": [
    {"id": "section-01", "order": 1, "title": "原文标题", "slides": []}
  ],
  "verbatimBlocks": [
    {"id": "prompt-01", "text": "必须逐字保留的提示词", "sha256": "..."}
  ],
  "links": [
    {"url": "https://...", "label": "原文中的链接文字"}
  ],
  "media": [
    {"path": "images/example.png", "sourceOrder": 1, "role": "案例证据"}
  ]
}
```

HTML 页面使用以下稳定标记：

- 页面：`data-source-order="1"`，拆页可写 `1.1`、`1.2`。
- 提示词或代码块：`data-verbatim-id="prompt-01"`。
- 来源章节：`data-source-section="section-01"`。

交付前由 `scripts/validate-deck.mjs` 校验顺序、逐字块和链接。

## 3. 提示词与代码块零改动

提示词、系统指令、代码、JSON、命令、参数和链接属于逐字内容：

- 一个字、一个标点、一个空格、一个换行都不能擅自修改。
- 不做“语病优化”、同义词替换、全半角替换或 Markdown 美化。
- 不省略段落，不把长提示词改成摘要。
- 页面放不下时拆成连续页；每页可重复标题，但逐字内容按原顺序拼接后必须与来源一致。
- 视觉层可改变字体、背景、边框、行高和滚动方式，但不能改变 `textContent`。
- 观众可见的辅助说明可以重写成 takeaway，不能混进逐字块。

## 4. 链接必须能直接打开

原文中的 URL 和链接文字都要转换为真实 `<a>`：

```html
<a href="https://example.com" target="_blank" rel="noopener noreferrer">打开案例</a>
```

- 链接不可只作为普通文字展示。
- 不使用 iframe 内嵌第三方页面作为默认打开方式。
- 链接文字应说明目的，避免只写“点击这里”。
- 二维码页同时保留可点击文字链接，方便电脑端访问。

## 5. 案例页的默认组合

案例内容优先在同一页合理呈现：

1. 案例名称。
2. 一句金句、判断或对教师的迁移启发。
3. 视频播放器或核心图片。
4. 必要时补一个明确的观看任务或迁移场景。

若实测 16:9 画布出现溢出、文字小于可读下限或媒体小到失去证据价值，才拆成两页。拆页顺序通常是“案例判断/证据”在前，“完整视频/迁移任务”在后。

## 6. 图片和视频比例

- 用户提供的图片、截图、海报、二维码和视频按源文件真实比例显示。
- `object-fit: contain` 是证据素材的默认策略。
- 视频加载元数据后，以 `videoWidth / videoHeight` 同步外层播放框比例。
- 不因模板槽位强行改成 16:9、4:3 或 1:1。
- 只有为页面专门生成的装饰图、背景图或明确可裁切的照片，才按预设槽位比例 `cover`。
- 同组证据图可以统一最大高度和间距，但不能通过拉伸变形获得“整齐”。

## 7. 明显错误的处理边界

可以直接修正：

- 明显错别字、连续重复词、错误页码和失效的本地相对路径。
- 用户已经提供正确版本、原文可无歧义校对的内容。

必须保留并提示用户：

- 可能改变观点的句子。
- 无法核验的数字、机构名、时间和外部事实。
- 提示词、代码和命令中的疑似拼写问题。

## 8. 更新已有 PPT 时的优先级

1. 先读取 `htmlppt-user-state.json` 和浏览器最新保存态。
2. 以用户最新修改为基底，再增量改功能或设计。
3. 禁止用旧 HTML 整页覆盖用户已保存的文字、图片、位置、字号、颜色和新增元素。
4. 若源码结构必须变化，按 `local-editor-contract.md` 做迁移并建立整套备份。
