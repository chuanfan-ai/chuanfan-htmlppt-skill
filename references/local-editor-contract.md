# 本地编辑器与用户修改保护契约

> 兼容说明：本文件只用于迁移本仓库旧版内嵌编辑器和旧状态。新建或新修改的 HTMLPPT，其交互、编辑、保存和恢复规则以独立 `htmlppt-interaction-editor` Skill 为唯一事实来源。

本文件记录已经在真实培训 PPT 中使用、测试或因失败而确认必须补上的旧版规则。迁移旧项目时完整读取。

模板旧代码与本文冲突时，以本文为准；本文与独立 Skill 冲突时，以独立 Skill 为准。

---

## 1. 四种状态必须分清

| 名称 | 定义 | 允许变化 | 恢复范围 |
|---|---|---|---|
| 原稿基线 | 首次交付、尚未经过浏览器编辑的完整 deck | 创建后不可被普通保存覆盖 | 全套 PPT |
| 最新用户保存态 | 用户最后一次明确点击“保存”后看到的文字、媒体、位置、尺寸和样式 | 每次保存更新 | 全套 PPT |
| 当前页历史 | 某一页保存前或恢复前的页面快照 | 追加，不覆盖其他页 | 仅该页 |
| 整套 PPT 备份 | 某一时刻完整 deck 与全部编辑参数的快照 | 追加 | 全套 PPT |

硬规则：

- 后续模型修改时，**最新用户保存态是事实来源**，原稿基线只用于“恢复原稿”。
- “当前页历史”不是整套备份的另一种名字；它只列出当前页可恢复的快照。
- “重置当前页”只恢复当前页并清除该页调整，其他页和历史记录必须保持不变。
- “恢复原稿”恢复到不可变的原稿基线；执行前先创建“恢复原稿前版本”，历史记录不得随之清空。
- 恢复任何历史版本前，先自动创建“恢复版本前”备份，保证恢复操作本身可撤销。

## 2. 模型继续修改前的 P0 保护流程

用户在浏览器里点过“保存”后，修改可能只存在 `localStorage`，磁盘上的旧 `index.html` 不一定是最新版。任何模型在改功能、改设计或重排页面前，必须按以下顺序执行：

1. 确认准确的 deck 目录、打开地址和 `localStorage` 作用域；不要把同名旧目录当成当前项目。
2. 确认浏览器是否存在尚未落盘的最新用户保存态。
3. 如果存在，通过本地编辑服务或“导出已编辑 HTML / 状态 JSON”把它固化成可读取文件；仅看到旧 `index.html` 不算完成。
4. 复制完整 deck 目录作为带时间戳的备份，至少包含 HTML、`images/`、视频、编辑状态文件和素材清单。
5. 以固化后的最新用户保存态为输入，只修改用户指定的页面或功能。
6. 修改后重新打开同一路径，验证一条用户已改文字、一个位置/样式调整和一个媒体修改仍然存在。
7. 通过后才允许告诉用户“原有修改已保留”。

如果无法读取浏览器保存态，也没有导出文件，必须停下并说明缺少哪一步；不得假定磁盘 HTML 就是最新版。

### 绝对禁止

- 从旧 `index.html`、旧 `slides-fragment.html` 或旧生成稿重建整套 deck，再覆盖当前文件。
- 因为 `sourceRevision`、schema 版本或模板版本变化，就直接执行 `localStorage.removeItem(...)` 清空编辑数据。
- 未迁移用户数据就更换 storage key，并把“新 key 为空”当作没有用户修改。
- 设计某一页时顺手删除该页原有图片、视频或文字；只有用户明确授权才可删除。
- 只做文件语法检查就宣称保存、历史恢复或键盘隔离已经可用。

### 版本升级必须迁移的字段

至少迁移以下数据：

- 文字内容和富文本结构；
- 原图替换路径、新增图片路径；
- 新增文本和新增图片；
- 对象位置、宽高或缩放；
- 字号、字体颜色、单行状态；
- 删除状态；
- 当前页历史和整套备份；
- 原稿基线的标识与内容。

迁移失败时保留旧 key 和旧文件，不得先删后试。

## 3. 编辑模式与键盘隔离

### 3.1 进入和退出

- 默认不绑定 `E` 为编辑模式切换键。
- 进入编辑模式使用明确的“编辑”按钮；退出使用工具栏中的“完成 / 退出”按钮。
- 在编辑模式里输入字母 `E`、中文、数字或符号，不得改变编辑状态。
- `Escape` 可以关闭历史面板或图片放大层，但不得顺带退出编辑模式。

### 3.2 禁止编辑态翻页

编辑模式开启时，以下按键不得触发翻页：

- `ArrowLeft`、`ArrowRight`；
- `Space`；
- `PageUp`、`PageDown`。

当焦点位于 `input`、`textarea`、`select` 或 `[contenteditable="true"]` 时，所有演示快捷键都必须让位给原生输入行为。空格要能输入，左右键要能移动光标。演示层的 `keydown` 处理器必须先判断编辑状态和输入焦点，再处理翻页。

不要用多个互相不知道状态的全局 `keydown` 监听器分别控制编辑和翻页；必须共用同一个编辑状态，或在捕获阶段统一拦截。

## 4. 可编辑对象与工具栏

### 4.1 文字修改

- 标题、正文、列表、标签、强调文字、代码块、提示词和卡片正文都要进入可编辑选择器；不要只覆盖 `h1/h2/p/li`。
- 复杂组件使用显式 `[data-editable]` 标记，避免模型猜选择器。
- 编辑态通过 `contenteditable` 修改；退出编辑态时移除临时属性和选择框。
- 保存时保留文字内容，清理 `contenteditable`、选中态和拖动态等临时标记。

### 4.2 选择、拖动与缩放

- 文字、原始图片、用户新增文字和用户新增图片使用同一选择模型。
- 工具栏必须显示当前是否选中对象；没有选中时，缩放、字号、颜色、单行、替换和删除不得误操作其他元素。
- 位置使用 slide 坐标系中的百分比、`vw/vh` 或等价相对值保存，不保存当前屏幕的绝对像素坐标。
- 用户新增浮层优先使用百分比位置和尺寸；移动或缩放后不得超出页面到完全不可见。
- 通用缩放范围使用 `0.5–2.0`；文字字号使用 `12–160px`。超出范围时钳制，不继续累加异常值。
- 不要为了支持拖动，把整页改造成响应式流式布局。跨分辨率重构是单独任务，必须先备份并得到用户明确同意。

### 4.3 字号、颜色与单行

选中文字后必须支持：

- 字号减小 / 增大；
- “一行”开关，使用 `white-space: nowrap`；再次点击恢复原换行规则；
- 五个常用字体颜色快捷按钮：
  - 深蓝 `#14213d`
  - 蓝色 `#4c86ed`
  - 橙色 `#ff9638`
  - 灰色 `#65758c`
  - 白色 `#ffffff`

颜色按钮必须有 `title` 和 `aria-label`，不能只靠色块让用户猜。

### 4.4 添加文本与图片

- “添加文本”在当前页创建可选、可编辑、可拖动和可缩放的文本对象。
- 新增文本默认 `background: transparent`；演示态不显示边框，编辑态只显示虚线选择提示。
- “添加图片”在当前页创建独立图片对象，保留原始比例，默认使用 `object-fit: contain`。
- 图片替换和新增图片必须通过 `scripts/local-edit-server.py` 写入 `images/user-edits/`，HTML 和状态中只保存相对路径。
- 服务不可用时明确提示用户启动服务；禁止把大图片以 base64 长期写入 `localStorage`。

### 4.5 删除选中

- 按钮名称统一为“删除选中”，不能只叫“删除图片”。
- 同一个按钮负责删除当前选中的文字或图片，包括用户新增文本和新增图片。
- 只删除当前选中对象，不得按标签批量删除同类元素。
- 删除状态必须进入保存和历史快照；恢复版本或重置当前页后能找回。

## 5. 保存、刷新与持久化

- 文字、调整参数和历史可以使用以 deck 路径为作用域的 `localStorage`。
- 点击“保存”时，先创建“保存前版本”，再原子地写入完整工作态；不能只保存当前正在编辑的一个字段。
- 完整工作态至少包含：清理后的 deck HTML、调整参数、新增元素、媒体路径、删除状态、schema 版本和保存时间。
- 保存成功后刷新同一路径，页面内容、位置、尺寸、字号、颜色、单行状态、替换图片和新增元素必须全部恢复。
- `localStorage` 写入失败或空间不足时，自动导出“已编辑版本.html”或状态文件，并明确提示“已导出，未写入浏览器存储”；不能只弹一个模糊错误。
- 如果用户之后还会让模型改设计或功能，不能只依赖浏览器存储。保存流程必须提供“落盘 / 导出最新版”，让模型能以最新状态为输入。
- 交付或移动项目时带上整个 PPT 文件夹和 `images/user-edits/`。页面路径变化会改变 storage 作用域，不能承诺旧浏览器历史自动跟随。

## 6. 历史面板的可恢复设计

- 使用可视化面板或弹窗，不使用 `prompt()` 让用户手输版本编号。
- 面板至少显示：版本名称、时间、作用域、页码/页标题和“恢复此版本”按钮。
- 使用两个清晰标签：`当前页历史`、`整套 PPT 备份`。
- 当前页标签只显示当前页快照；整套标签显示完整 deck 快照。
- 恢复前弹出简短确认，并先自动保存当前状态。
- 删除历史版本必须单独确认；删除一个版本不能影响当前工作态和其他版本。

## 7. 视觉与屏幕验收边界

- 默认按用户声明的演示比例设计；未明确时以 `16:9` 为主验收比例。
- 编辑对象使用相对坐标，只解决对象编辑的稳定性，不等于整套 PPT 已实现任意分辨率响应式重排。
- 用户没有明确要求时，不主动加入移动端单列重排、全套 canvas 缩放或其他架构级响应式改造。
- 至少在目标演示尺寸和一个常见笔记本尺寸打开全套页面，检查：
  - 左上角 kicker / 章节标签不压住标题；
  - 右边缘没有异常白条或画布露底；
  - 标题、图片、视频、页码和导航没有重叠；
  - 用户拖动后的对象没有跑出画布；
  - 编辑工具栏在常见宽度下仍可点击。

发现不同屏幕差异时，先报告具体页面和原因，再决定是否做整套缩放方案；不要在一次普通页面修改里悄悄重构整个坐标系统。

## 8. 最小真实验收

每次新建或修改编辑器后，必须在浏览器实际完成以下操作：

1. 进入编辑模式，输入含 `E` 的文字，确认没有退出。
2. 在文字中按左右键和空格，确认光标/输入正常且没有翻页。
3. 添加文本，退出编辑模式，确认文本没有背景色和编辑边框。
4. 添加图片，确认文件落在 `images/user-edits/` 且使用相对路径。
5. 分别拖动和缩放一个文本、一个图片，刷新后确认位置和尺寸保留。
6. 调整字号、五种颜色和“一行”状态，刷新后确认保留。
7. 分别选择文字和图片执行“删除选中”，确认只删除当前对象。
8. 保存后刷新，确认全部修改恢复。
9. 打开“当前页历史”，恢复一条当前页版本，确认其他页不变。
10. 打开“整套 PPT 备份”，恢复一条整套版本，确认整套状态一致。
11. 执行“重置当前页”，确认只有当前页回到原稿基线。
12. 执行“恢复原稿”，确认历史仍存在并可恢复“恢复原稿前版本”。
13. 在保存一条独特测试文字后，再做一次代码级页面修改；重新打开后确认该测试文字仍在。这一项用于防止模型拿旧源文件覆盖用户最新修改。

以上任一项未实测，不得用“已完成”“不会丢失”“跨屏一致”等确定性措辞交付。
