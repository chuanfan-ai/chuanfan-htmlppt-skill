# HTMLPPT 配图与提示词规范

本文件约束配图的来源选择、生成提示词和落位方式，不绑定某一家图片模型。先确定页面任务、素材真实性和目标槽位，再决定是否需要生成图片。

## 1. 供应商与失败边界

- 图片供应商和模型由用户或当前运行环境明确指定；Skill 不自行更换。
- 用户指定供应商后，超时、限流、余额不足或内容审核失败时，只允许：原模型重试、使用已有素材、改用可编辑 HTML/CSS/SVG，或明确报告失败。
- 禁止静默切换到其他付费图片模型。特别是运行环境明确禁止 GPT 生图时，任何步骤都不得以“自动兜底”为由调用 GPT。
- API Key 只保存在服务端；提示词、日志、HTML、`asset-manifest.json` 和前端都不得记录 Key。
- 供应商支持的比例或像素与目标槽位不一致时，由运行时选择最接近的可用比例，再用等比裁切、留白或程序化画布适配；禁止拉伸。

## 2. 配图路由顺序

按以下顺序选择素材，停在第一个能满足页面目标的层级：

1. **用户证据素材**：原图、截图、海报、二维码、视频和文档图片。
2. **真实公开素材**：官方网站、用户明确授权的图库或可核验网页素材。
3. **可编辑图形**：流程、数据、对比、时间线、系统关系和短标签信息图使用 HTML/CSS/SVG。
4. **生成图片**：封面、章节主视觉、抽象概念、氛围场景和不对应真实事件的示意画面。

真实人物、学校、企业、产品、活动和案例不得用生成图冒充现场照片。用户素材是证据时默认 `object-fit: contain`，不裁掉文字、二维码或关键界面。

## 3. 生成图的内容边界

生成图默认只负责视觉，不负责排版：

- 不在图片中生成标题、正文、页码、页眉、页脚、角标、署名、logo 或 PPT 外壳。
- 不把流程文字、数据标签、引用和中文长句烘焙进图片。
- 页面文字、图表和关系线由 HTML/CSS/SVG 承担，保持准确、清晰和可编辑。
- 同一组图片保持相同画幅、主体尺度、边距、光线、色彩和视觉密度。
- 不生成卡通机器人、虚假 dashboard、霓虹科技感、蓝紫渐变、3D 装饰或无法解释的假品牌。

## 4. 先定槽位，再准备图片

| 页面用途 | 目标槽位 | 推荐策略 |
|---|---|---|
| 封面、章节主视觉 | 16:9 | 生成或选取横向主视觉，预留标题安全区 |
| 瑞士风顶部横幅 | 21:9 | 先生成最接近的横图，再等比裁切到 21:9 |
| 左文右图 | 16:10 或 4:3 | 主体放在远离文字的一侧，保留负空间 |
| 案例与真实截图 | 原比例 | 程序化画布适配，默认 `contain` |
| 多图网格 | 统一 3:2、4:3 或 16:9 | 同组全部使用同一比例和主体尺度 |
| 信息图、流程、数据 | 16:9 页面区域 | 优先 HTML/CSS/SVG，不调用图片模型 |

如果供应商不支持 21:9 或 16:10，运行时先生成 16:9、4:3 等可用横图，再进行无拉伸裁切或加背景留白。裁切前确保人物脸部、产品主体和关键视觉落在中央安全区。

## 5. 通用提示词结构

每张生成图都按以下顺序组织，不写成长篇制作说明：

```text
页面任务：[封面 / 章节 / 概念场景 / 氛围视觉]
核心主题：[一句话说明画面表达]
视觉风格：[风格 A / B / C 的具体规则]
构图：[目标比例、主体位置、负空间方向、安全区]
光线与色彩：[真实、克制、与当前主题一致]
一致性：[同组图片的主体尺度、边距、线条或光线要求]
禁止项：不要文字、logo、水印、页眉、页脚、标题栏、页码、角标、装饰边框、PPT 外壳、卡通机器人、霓虹科技感和虚假品牌。
```

通用规格后缀：

```text
输出为横向构图，主体完整并保留边距，核心视觉位于安全区，画面密度中等。只生成画面本身，不生成任何文字、logo、水印、页眉、页脚、标题、页码、角标、署名、装饰边框或幻灯片外壳。
```

同一页或同一组需要多张图时追加：

```text
这是一组视觉素材中的一张。与同组图片保持相同画幅、主体大小、视角、边距、光线、色彩和细节密度。
```

## 6. 风格 A：电子杂志 × 电子墨水

适合品牌叙事、观点演讲、人文主题和电影感发布。视觉关键词：真实纪实、低饱和、自然光、纸张气质、克制留白、编辑部摄影。

### A1. 人文纪实主视觉

```text
生成一张横向编辑部纪实摄影，主题是：[页面概念]。真实工作或生活现场，自然光，低饱和，轻微胶片颗粒，克制而有人文温度。构图为[16:9 / 4:3 / 3:2]，主体位于[左侧 / 右侧 / 中央]，在[左侧 / 右侧]预留大面积干净负空间。不要商业摆拍、科幻界面、AI 机器人、文字、logo 或水印。
```

### A2. 抽象概念画面

```text
生成一张横向抽象编辑视觉，表达：[抽象概念]。使用真实材质、纸张、光影、建筑或日常物件建立隐喻，黑白灰为主，少量低饱和强调色，留白充足，像高端独立杂志跨页摄影。不要信息图文字、卡通、3D、霓虹、logo 或幻灯片外壳。
```

## 7. 风格 B：瑞士国际主义

适合设计系统、产品发布、结构化报告和强网格演示。图片本身不承担瑞士排版；网格、文字、线条和色块由 HTML 模板完成。

视觉关键词：Swiss editorial documentary、冷静、高对比、黑白灰、单一 accent、负空间、准确裁切、无装饰。

### B1. 顶部横幅或案例主图

```text
生成一张超宽横向纪实摄影，主题是：[页面概念]。Swiss editorial documentary 风格，高对比、低饱和、冷静克制、真实办公/城市/产品使用场景。主体位于中央 70% 安全区，左右保留可裁切负空间，适合最终裁切为 21:9。不要文字、logo、水印、圆角面板、渐变、阴影、3D 或 PPT 外壳。
```

### B2. 极简抽象主视觉

```text
生成一张横向极简抽象视觉，表达：[概念]。使用几何实体、建筑切面、纸张或真实材质，黑白灰和一个[IKB 蓝 / 柠檬黄 / 柠檬绿 / 安全橙]强调色，严格负空间，主体位于网格交点附近。不要生成任何文字、流程线、数据标签、logo、阴影、渐变、圆角或幻灯片外壳。
```

## 8. 风格 C：船帆大会培训

适合学校/企业培训、大会分享、AI 方法教学、工具教程和案例密集长篇 deck。风格 C 以真实证据和可读教学为主，生成图只承担封面、章节和少量概念视觉。

视觉关键词：现代中文大会、真实培训现场、浅色主导、清晰、可信、蓝色方法、橙色行动、少量深色舞台页。

### C1. 大会或培训封面主视觉

```text
生成一张横向大会培训主视觉，主题是：[演讲主题]。真实、现代、可信，使用简洁空间、自然人物活动或抽象光线表现学习与协作。色彩以白、黑和克制的品牌蓝为主，少量品牌橙只作行动提示。主体位于[左侧 / 右侧]，另一侧保留大面积干净标题区。不要舞台文字、logo、机器人、霓虹、蓝紫渐变、水印或幻灯片外壳。
```

### C2. AI 方法与协作场景

```text
生成一张横向真实工作场景摄影，表达：[教师备课 / 企业讨论 / AI 工具实践 / 团队共创]。人物与设备关系自然，界面内容不需要可读，不冒充具体软件截图。浅色环境、清晰结构、品牌蓝小面积出现，画面可信、克制、适合中文培训课件。不要商业摆拍、假 logo、可识别虚构文字、AI 机器人或科技霓虹。
```

### C3. 章节转场抽象视觉

```text
生成一张横向章节转场视觉，表达：[关键判断或转折]。深色舞台感但不过度发光，使用黑色、深蓝、真实材质或单一光束建立停顿，少量橙色表示行动。中央视觉简洁，四周保留安全区。不要文字、logo、赛博霓虹、复杂 dashboard 或幻灯片外壳。
```

## 9. 截图与界面素材

真实截图按以下顺序处理：

1. 内容需要保真时读取 `screenshot-framing.md`，使用目标比例画布、风格背景、等比缩放和语义化留白。
2. 原图接近目标比例时直接放入统一 frame，使用 `contain` 或经过确认的 `cover`。
3. 过高、过窄或过长的界面拆成 2–3 张同尺寸局部面板。
4. 只有用户明确允许“示意重绘”时才生成界面情景图，并标注为示意，不冒充真实产品截图。

图片模型生成的界面文字不可靠。需要展示真实操作、按钮、代码或提示词时，必须使用原截图或 HTML 重构。

## 10. 素材记录

自动化运行时为生成图和联网素材维护 `asset-manifest.json`。最小结构：

```json
{
  "assets": [
    {
      "slideId": "slide-01",
      "sourceType": "user|official|web|generated|html-svg",
      "source": "原文件、来源 URL 或供应商名称",
      "model": "仅生成图填写",
      "prompt": "仅生成图填写，不含密钥",
      "targetRatio": "16:9",
      "file": "images/01-cover.jpg",
      "fallback": "失败时采用的已有素材或可编辑图形"
    }
  ]
}
```

不在清单中写入 API Key、Authorization、Cookie、Token、用户隐私或临时签名下载地址。

## 11. 交付检查

- [ ] 图片供应商与用户或运行环境指定一致，没有静默切换。
- [ ] 真实人物、机构、产品和案例没有被生成图冒充。
- [ ] 页面文字、流程、数据和引用仍可编辑，没有烘焙进生成图。
- [ ] 用户原图、截图、二维码和视频保持源比例。
- [ ] 图片比例与槽位一致，未拉伸，关键主体未被裁掉。
- [ ] 同组图片的尺度、边距、色彩和视觉密度一致。
- [ ] `asset-manifest.json` 不含密钥和敏感信息。
