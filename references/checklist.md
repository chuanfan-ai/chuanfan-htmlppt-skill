# HTMLPPT 交付质量门禁

本清单只保留跨项目、可验证的验收条件。风格细节分别读取对应参考文件，不能把 A、B、C 的规则混用。

## 0. 规则优先级

1. 用户本轮明确要求。
2. 用户最新保存态与 `references/local-editor-contract.md`。
3. 飞书来源与 `references/feishu-content-contract.md`。
4. 当前选择的风格规范与模板。
5. 本清单的通用建议。

发生冲突时按以上顺序执行。不得用低优先级的“视觉统一”覆盖用户内容、逐字提示词或最新编辑状态。

## 1. P0：用户修改与编辑器

生成、修改或验收编辑器前，完整读取 `references/local-editor-contract.md`。

- [ ] 已确认浏览器/本地状态文件中的用户最新保存态。
- [ ] 后续设计修改以最新保存态为基底，没有从旧 HTML 覆盖用户文字和位置。
- [ ] 修改源码前已创建整套 PPT 备份。
- [ ] schema 或源码 revision 变化时执行迁移，没有清空旧存储键。
- [ ] 只能点击编辑按钮进入/退出编辑模式；输入 `E` 不退出。
- [ ] 编辑模式下左右键、空格、PageUp/PageDown 不翻页。
- [ ] 标题、正文、卡片、提示词、代码块和 `[data-editable]` 可编辑。
- [ ] 文字和图片都可选择、拖动、缩放和删除。
- [ ] 添加文本默认透明，无演示态背景和虚线框。
- [ ] 可调字号、深色、品牌蓝、品牌橙、灰、白与单行显示。
- [ ] 图片替换/新增写入 `images/user-edits/`，不把大图 base64 存进状态。
- [ ] 保存后刷新恢复；状态可落盘为 `htmlppt-user-state.json`。
- [ ] 当前页历史与整套备份分栏可见，可点击恢复，不使用编号输入框。
- [ ] 重置当前页只影响当前页；恢复原稿恢复不可变基线且保留历史。

## 2. P0：来源内容忠实

使用飞书文档或其他明确原稿时，完整读取 `references/feishu-content-contract.md`。

- [ ] 已建立 `source-manifest.json`。
- [ ] 页面 `data-source-order` 与来源顺序一致。
- [ ] 正文尽可能完整保留；删改已得到授权或属于可无歧义纠正的错误。
- [ ] 每个提示词/代码块都有 `data-verbatim-id`。
- [ ] 逐字块的字符、标点、空格和换行校验通过。
- [ ] 原文链接是可直接打开的 `<a>`，包含 `_blank` 和 `noopener noreferrer`。
- [ ] 案例页优先呈现案例名称、金句、媒体和迁移启发。
- [ ] 观众文案是 takeaway，不出现“这页放视频”“原文保留”等制作说明。

## 3. P0：媒体真实性

- [ ] 用户提供的截图、海报、二维码和证据图片保持源比例，默认 `object-fit: contain`。
- [ ] 用户视频读取真实 `videoWidth / videoHeight`，外层播放框比例与源视频一致。
- [ ] 二维码清晰可扫，同时提供文字链接。
- [ ] 只有专门生成的装饰图、背景图或明确可裁照片才使用标准槽位比例与 `cover`。
- [ ] 同组证据图通过最大高度、边距和网格对齐，不通过拉伸或裁掉文字来“统一”。
- [ ] 本地资源使用相对路径，移动整个文件夹后仍能打开。

## 4. P0：画布与响应稳定

- [ ] 每页固定设计比例，整张幻灯片作为一个整体等比缩放适配屏幕。
- [ ] 页面内部没有因浏览器宽度变化再次独立重排的关键对象。
- [ ] 左上角栏目标签不压大标题。
- [ ] 右上角说明不压导航按钮。
- [ ] 底部内容、页码、进度条和工具栏互不遮挡。
- [ ] 标题无单字孤行，正文无超出画布，媒体无出界。
- [ ] 至少检查 1920×1080、1440×900、1366×768 三个视口。
- [ ] 全屏和非全屏截图的相对位置一致。

说明：如果现有 deck 没有采用整页等比缩放，不为单个小需求强行改造整套响应系统；先记录风险，并按用户授权范围处理。

## 5. P1：风格 A

使用 `assets/template.html` 时：

- [ ] 完整读取 `references/layouts.md` 与 `references/themes.md`。
- [ ] 标题衬线、正文无衬线，类名必须来自模板。
- [ ] 明暗页有节奏，不连续堆叠同一种 hero。
- [ ] WebGL 与当前页面明暗匹配，正文可读。
- [ ] 不混用 Swiss 或风格 C 的类名。

## 6. P1：风格 B

使用 `assets/template-swiss.html` 时：

- [ ] 完整读取 `references/swiss-layout-lock.md`、`references/layouts-swiss.md`、`references/themes-swiss.md`。
- [ ] 正文页从登记的 Swiss 版式中选择，顶部标题沿左上内容轴。
- [ ] 封面/封底、ASCII 场、地图组件和字号阶梯符合对应规范。
- [ ] 直角、单一强调色、网格和细线优先，不加沉重阴影。
- [ ] 不混用风格 A 或 C 的类名。

## 7. P1：风格 C

使用 `assets/template-conference.html` 时：

- [ ] 完整读取 `references/style-c-conference-training.md` 与 `references/chuanfan-brand.md`。
- [ ] 船帆本人且无其他说明时，品牌色来自个人网站：`#090909 / #1677ff / #ff7a00`。
- [ ] 长培训以浅色教学页为主，深色用于关键判断与节奏页。
- [ ] 黑色承担结论、蓝色承担方法、橙色承担行动，语义稳定。
- [ ] 真实截图、提示词、流程和视频是页面主体，不拿来做模糊背景。
- [ ] 至少交替使用 4 类页面配方，不能连续复制同一空卡片结构。
- [ ] 不出现全套深色、蓝紫渐变、赛博发光或大面积橙底。

## 8. P1：文字与信息层级

- [ ] 每页有一个明确主结论。
- [ ] Kicker、标题、正文、注释层级清楚，避免多个元素争抢第一视觉。
- [ ] 内容较多时拆页，避免把正文压到不可读字号。
- [ ] 中英文术语、引号、数字格式和机构名称全套一致。
- [ ] 不使用 emoji 代替正式图标。
- [ ] 链接、按钮和二维码旁的行动指令明确。

## 9. P1：交互与演示

- [ ] 演示模式左右键、空格、PageUp/PageDown、Home/End 正常。
- [ ] 编辑模式完全隔离上述翻页键。
- [ ] 滚轮和触屏在编辑模式不翻页。
- [ ] 页码、总页数、hash 和实际页面一致。
- [ ] 外部链接在演示模式可以打开新标签页。
- [ ] 视频可播放、有控件、不会因翻页残留错误状态。
- [ ] 全屏按钮与 Esc 退出正常。

## 10. 自动化与真实浏览器验收

至少执行：

```bash
python3 scripts/sync-editor-core.py --check
node scripts/validate-deck.mjs path/to/index.html --manifest path/to/source-manifest.json
node tests/editor-contract.test.mjs
```

视觉验收必须打开真实浏览器，不只检查 HTML/CSS：

1. 截取关键页面：封面、密集文字、图片、提示词、视频、行动页。
2. 对照来源文档和参考 PPT。
3. 检查重叠、溢出、孤行、媒体比例和明暗节奏。
4. 再跑编辑器键盘、保存、刷新、历史、重置和恢复流程。

## 11. 交付结论

只有以下条件全部满足，才可以声称完成：

- P0 全部通过。
- 所选风格的 P1 全部通过。
- 自动校验退出码为 0。
- 真实浏览器回归通过。
- 变更范围与用户授权一致。
- 未修改用户明确要求保持不变的文件。
